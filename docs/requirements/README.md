# PRD: 星星 (DayDayUp - Tiny Realms 微界)

> 版本: 1.0-MVP
> 最后更新: 2026-02-01
> 产品定位: 基于福格行为模型的人生愿望修炼游戏

---

## 一、背景与问题

### 1.1 当前痛点

**现有习惯类产品的核心问题:**

1. **工具化而非游戏化**: 传统习惯打卡App本质是"打勾工具",缺乏情绪价值和长期驱动力,用户在新鲜感消失后迅速流失。
2. **目标设定过高**: 用户常设定"每天跑步30分钟"这类难以坚持的宏大目标,导致挫败感累积,最终放弃。
3. **缺乏行为探索引导**: 产品假设用户"知道自己该做什么",但实际上大部分人不清楚如何将愿望拆解为可执行的微行动。
4. **反馈机制单薄**: 简单的打勾、连续天数记录等反馈过于抽象,缺乏即时性、趣味性和成长感。
5. **方法论工具vs可玩游戏**: 福格行为模型(Tiny Habits)作为有效方法论,尚未被成功转化为"可长期玩的游戏"。

### 1.2 机会分析

**市场机会:**
- **用户需求旺盛**: 习惯养成、自我管理、生活优化是持续存在的刚需,覆盖18-45岁广泛人群。
- **微信生态红利**: 小程序"用完即走、无需下载"的特性,降低用户使用门槛,适合碎片化场景。
- **游戏化趋势**: Duolingo证明了"轻量游戏化+强反馈+低摩擦"能显著提升用户留存和完成率。
- **认知升级价值**: 产品不仅帮用户"完成习惯",更能引导用户"理解自己、澄清愿望、探索行为",具备长期价值。

**技术机会:**
- 福格行为模型(B=MAP,行为=动机×能力×提示)提供科学框架。
- 游戏化设计成熟方法论(核心循环、即时反馈、成长系统)可直接应用。
- AI技术未来可用于行为推荐、智能裂变、个性化引导(MVP暂不实现)。

### 1.3 受影响用户

**核心受益群体:**
- **18-30岁职场新人**: 希望建立良好习惯,提升自我管理能力。
- **25-40岁都市白领**: 追求自我成长、生活品质优化,但时间有限。
- **习惯养成爱好者**: 尝试过多款习惯App但未成功的用户,需要新的解决方案。
- **自我探索型用户**: 对"认识自我、澄清愿望"有强烈需求的用户。

## 二、目标

### 2.1 必须达成的业务/用户目标

**MVP阶段核心目标(按优先级排序):**

| 优先级 | 目标类型 | 目标描述 | 验收标准 |
|-------|---------|---------|---------|
| P0 | 玩法验证 | 验证"愿望排序+行为工坊+每日卡片"的核心玩法能让用户持续使用 | 完成7天主线的用户占比 ≥ 30% |
| P0 | 用户完成率 | 用户能够理解并完成每日微行动卡 | 日均完成微行动卡的用户占比 ≥ 50% |
| P0 | 技术可行性 | 验证小程序技术方案可行,无重大性能或兼容性问题 | 主要功能流程可正常运行,崩溃率 < 1% |
| P1 | 留存率 | 用户愿意持续使用产品 | 次日留存 ≥ 40%,7日留存 ≥ 20% |
| P1 | 用户反馈 | 收集种子用户深度反馈,优化产品方向 | 获得 ≥ 100 名深度体验用户,NPS ≥ 40 |
| P2 | 数据洞察 | 积累用户行为数据,为后续迭代提供依据 | 完整记录用户关键行为路径和流失节点 |

**长期愿景(MVP后):**
- 成为"人生技能养成游戏"的标杆产品,而非"习惯打卡工具"。
- 让用户在"玩"的过程中,自然形成行为、澄清愿望、理解自我。
- 建立用户长期留存机制(角色成长线、世界成长线、认知成长线)。

### 2.2 非目标(本期明确不做的范围)

**明确排除的功能(避免范围蔓延):**

1. **社交功能**: 不做好友系统、分享功能、排行榜、组队打卡等(避免复杂度,聚焦核心玩法)。
2. **复杂数据分析**: 不做详细统计图表、行为洞察报告、AI推荐(MVP阶段只做本地存储)。
3. **习惯分类管理**: 不做习惯分类、标签、搜索、筛选等管理功能(简化交互)。
4. **提醒推送**: 不做定时提醒、消息推送功能(避免打扰,MVP依赖用户主动打开)。
5. **商业化功能**: 不做会员、道具购买、广告等变现功能(MVP聚焦验证玩法)。
6. **多端适配**: 只做微信小程序,不做App、H5、桌面端。
7. **外部集成**: 不做第三方服务集成(如健康数据、日历同步等)。

## 三、用户画像与场景

### 3.1 主要用户角色

#### 角色1: 职场新人小李(24岁,产品经理)

**基本信息:**
- 毕业2年,在互联网公司工作,收入稳定。
- 关注自我提升,尝试过Forest、滴答清单、微信读书打卡等工具。
- 有一定自律性,但容易三分钟热度,需要外部激励。

**需求痛点:**
- 设定的目标过大("每天健身1小时"),执行困难,挫败感强。
- 不知道如何将"变得更健康"拆解为可执行的微行动。
- 传统打卡App太枯燥,缺乏成就感和趣味性。

**使用场景:**
- **工作日晚上**: 下班后打开小程序,完成"每日一张微行动卡"(如"刷牙后做2个深蹲"),获得即时反馈。
- **周末早晨**: 进入"行为工坊",探索新的微习惯,调整自己的行为卡组。
- **通勤路上**: 查看自己的7天进度,感受"愿望城"的修复进展。

**目标达成:**
- 通过每日完成微行动,建立"我能做到"的自信。
- 在游戏化引导下,逐步澄清自己的核心愿望(健康、成长、财务自由等)。

---

#### 角色2: 自我探索型用户小王(30岁,自由职业者)

**基本信息:**
- 关注个人成长、心理学、正念等领域。
- 希望通过行为实验了解自己,而非简单"打卡完成任务"。
- 对有深度、有意义的产品有较高付费意愿。

**需求痛点:**
- 传统习惯App太功能化,缺乏"探索自我"的深度。
- 想要一个能帮助自己"思考人生愿望"的工具,而非只是记录习惯。
- 希望产品能提供引导,而非只是空白表单。

**使用场景:**
- **睡前反思**: 完成每日微行动后,查看"裂隙宣言"被击碎的动画,感受自己战胜内心阻力的成就感。
- **周末深度使用**: 进入"愿望排序游戏",通过两两对决和命运盘拖拽,澄清自己当前阶段的核心愿望。
- **月度回顾**: 完成第一座愿望城修复后,选择下一座愿望城,感受人生优先级的演进。

**目标达成:**
- 通过产品引导,完成一次深度的"内心优先级博弈"。
- 在"玩"的过程中,理解福格行为模型,学会拆解宏大目标。

### 3.2 关键场景

#### 场景1: 首次使用流程(第1天)

**场景描述:**
1. 用户从朋友推荐/搜索发现小程序,点击进入。
2. 看到"愿望大陆被裂隙之影侵蚀"的世界观开场(3-5行文案+插画占位)。
3. 点击"开始修复",进入角色创建页,选择天赋(火花型/潮汐型/石匠型/风行型)。
4. 进入愿望排序游戏:
   - 两两对决(7轮),每轮选择"更想靠近的那个愿望"。
   - 拖拽排序到"命运盘"(核心愿望/主线愿望/以后再说)。
5. 确认核心愿望后,进入"魔法师行为工坊":
   - 点击"召唤灵感",出现3个行为气泡,选择1个加入素材区。
   - 对"较大行为"点击"裂变",生成3个更小行为。
   - 选择2个行为点击"合成",生成新咒语。
   - 最终生成3张卡(保底卡/主线卡/彩蛋卡)。
6. 进入"每日一张微行动卡"页面:
   - 看到今日卡片(如"刷牙后,喝一杯水",30秒,难度★)。
   - 点击"开始施放" → 完成后点击"完成"。
   - 裂隙宣言卡从底部滑入("今天太忙了,算了吧"),点击"击碎"。
   - 背景变亮,Arc导师出现:"你不需要更努力,你需要更小一点。"
   - 显示Day 1完成,+10分。

**关键成功要素:**
- 世界观引导清晰,不超过30秒理解。
- 愿望排序游戏有"博弈感",不是简单填表。
- 行为工坊有"探索感",召唤/裂变/合成都有明显反馈。
- 每日卡片完成后,"击碎裂隙"动画必须有"爽感"。

---

#### 场景2: 日常使用(第2-6天)

**场景描述:**
1. 用户每天打开小程序,自动进入"每日一张微行动卡"页面。
2. 看到Arc/Rift的对话框(如Day 2: "今天太忙了,算了吧" → "只施放一次咒语,就够了")。
3. 看到今日抽取的卡片(默认保底卡,连续2天完成则30%概率抽主线卡)。
4. 完成微行动后,击碎裂隙宣言,获得Arc的鼓励台词。
5. Day推进+1,积分增加,streak更新。

**备选路径:**
- 如果用户当天未完成(todayDone=false),第二天自动降级为"救援卡"(从保底卡或预置救援卡池抽取)。
- 用户可随时进入"行为工坊"调整卡组,但非必需。

**关键成功要素:**
- 每日进入流程简洁,2步内完成(打开小程序 → 看到今日卡)。
- 完成反馈必须有"三段式"(裂隙卡滑入 → 击碎动画 → 鼓励台词)。
- 未完成时不惩罚,提供"救援卡"降低压力。

---

#### 场景3: 完成7天主线(第7天)

**场景描述:**
1. 用户完成Day 7的微行动卡。
2. Arc导师出现:"第一座愿望城修复完成。微光会带你去下一座城。"
3. 背景动画:愿望城从"荒地"变为"村庄",发出金色光芒。
4. 弹出选择:"选择下一座愿望城"(可重新进入愿望排序游戏,选择第二个核心愿望)。
5. Day重置为1,保留角色天赋、已解锁咒语图鉴、历史记录。
6. 用户进入下一个7天循环。

**关键成功要素:**
- 完成7天必须有"里程碑庆祝"(动画+音效+台词)。
- 提供明确的"下一步行动"(选择下一座愿望城),避免流失。
- 历史记录保留,让用户感受到"积累感"。

#### 6.1.2 每日完成幂等性

**规则:**
- 同一天只能完成一次微行动卡,即使用户多次点击"完成"按钮。
- 完成判定基于本地日期字符串(toDateString()),不依赖服务器时间。
- 完成后todayDone设为true,lastDoneDate更新,按钮置灰。

**实现:**
```javascript
completeHabit() {
  const state = loadState();
  const today = new Date().toDateString();

  if (state.todayDone && state.lastDoneDate === today) {
    wx.showToast({ title: '今日已完成', icon: 'none' });
    return;
  }

  // 正常完成流程...
  state.todayDone = true;
  state.lastDoneDate = today;
  saveState(state);
}
```

#### 6.1.3 连续天数(Streak)计算逻辑

**规则:**
- Streak初始值为0。
- 首次完成微行动,Streak=1。
- 若lastDoneDate是昨天,Streak+1(连续保持)。
- 若lastDoneDate是今天,阻止重复完成(幂等性)。
- 若lastDoneDate>1天前,Streak重置为1(断连)。

**实现:**
```javascript
updateStreak() {
  const state = loadState();
  const today = new Date();
  const lastDate = state.lastDoneDate ? new Date(state.lastDoneDate) : null;

  if (!lastDate) {
    state.streak = 1;  // 首次完成
  } else {
    const yesterday = new Date(today);
    yesterday.setDate(yesterday.getDate() - 1);

    if (lastDate.toDateString() === yesterday.toDateString()) {
      state.streak += 1;  // 连续
    } else if (lastDate.toDateString() === today.toDateString()) {
      return false;  // 今日已完成
    } else {
      state.streak = 1;  // 断连重置
    }
  }

  if (state.streak > state.bestStreak) {
    state.bestStreak = state.streak;
  }

  saveState(state);
  return true;
}
```

#### 6.1.4 卡片抽取概率

**规则:**
| 连续完成天数 | 保底卡概率 | 主线卡概率 | 彩蛋卡概率 |
|-------------|-----------|-----------|-----------|
| 首次/断连 | 100% | 0% | 0% |
| 连续1天 | 100% | 0% | 0% |
| 连续2天+ | 60% | 30% | 10% |

**实现:**
```javascript
drawTodayCard(deck, streak) {
  if (streak < 2) {
    return deck.find(card => card.type === 'base');  // 保底卡
  }

  const rand = Math.random();
  if (rand < 0.1) {
    return deck.find(card => card.type === 'bonus') || deck.find(card => card.type === 'base');
  } else if (rand < 0.4) {
    return deck.find(card => card.type === 'main') || deck.find(card => card.type === 'base');
  } else {
    return deck.find(card => card.type === 'base');
  }
}
```

#### 6.3.3 内容审核标准

**愿望库审核规则:**

**台词库审核规则:**
- 禁止: 负面情绪过重的台词(如"你真没用""放弃吧")。
- 允许: 温和引导、正向鼓励的台词。
- Rift(裂隙之影)的阻力宣言,必须是"可被击碎"的轻量阻力,而非羞辱。

**示例:**
- ✅ "今天太忙了,算了吧" → 击碎后 → "只施放一次咒语,就够了"
- ✅ "这点做了也没用" → 击碎后 → "那就让它更小,小到无法拒绝"
- ❌ "你这么懒,注定失败" → 过于负面,不使用

## 八、风险与假设

### 8.1 关键风险

#### 风险1: 用户理解成本高(P0 - 高风险)

**风险描述:**
- 福格行为模型、游戏化世界观对普通用户可能过于抽象。
- 用户可能不理解"愿望城""裂隙之影""微行动咒语"等概念,导致困惑流失。
- 愿望排序、行为工坊等玩法可能被认为"太复杂",不如直接打卡简单。

**影响:**
- 用户在Onboarding/Role/Wishes阶段流失率高(>50%)。
- Day 1完成率<60%。

**缓解措施:**
1. **简化文案**: 世界观引导不超过3行,使用简单口语化表达(如"修复你的愿望大陆")。
2. **新手引导**: 在Onboarding/Role/Wishes页增加"轻提示气泡",解释每一步要做什么。
3. **即时反馈**: 每个操作都有明显动画反馈,让用户知道"这一步有效"。
4. **跳过选项(备选)**: 提供"快速开始"按钮,使用默认愿望+默认卡组,让用户先体验Daily。

**监控指标:**
- 各页面流失率(Onboarding→Role→Wishes→Workshop→Daily)。
- 用户反馈中"不理解""太复杂"的提及率。

---

#### 风险2: 玩法深度不足(P0 - 高风险)

**风险描述:**
- 7天主线完成后,缺乏长期留存机制,用户流失。
- "选择下一座愿望城"可能只是重复7天流程,缺乏新鲜感。
- 行为工坊在首次生成卡组后,缺乏再次进入的动力。

**影响:**
- Day 7完成后,回流率<30%(目标≥50%)。
- 总体7日留存率<15%(目标≥20%)。

**缓解措施:**
1. **MVP阶段**: 优先验证"前7天玩法是否有吸引力",暂不解决长期留存问题。
2. **下一版本**: 引入"角色成长线"(等级/技能解锁)、"世界成长线"(愿望城进化可视化)、"认知成长线"(行为复盘局)。
3. **内容扩展**: 增加愿望库、行为库、台词库的丰富度,让"选择下一座愿望城"有更多选择。
4. **社交机制(长期)**: 引入轻量社交(查看朋友的愿望城进度),增强社交驱动。

**监控指标:**
- Day 7完成后7天内的回流率。
- 用户反馈中"没意思了""不想玩了"的提及率。

---

#### 风险3: 内容库不足(P1 - 中风险)

**风险描述:**
- 愿望库、行为库、裂变规则库、台词库需要大量人工编写和维护。
- MVP阶段资源有限,内容库可能不够丰富,导致重复感。
- 行为召唤、裂变、合成可能频繁出现重复内容。

**影响:**
- 用户在行为工坊多次召唤,发现都是相同行为,体验变差。
- 裂隙宣言、Arc台词重复出现,失去新鲜感。

**缓解措施:**
1. **MVP最小内容量**:
   - 愿望库:至少12张默认愿望+支持用户自定义。
   - 行为库:每个愿望至少10个行为(12*10=120个行为)。
   - 裂变规则库:至少20条规则(如"跑步→穿鞋/站起来/出门")。
   - 台词库:Arc/MIA/Rift各至少20条台词,保证Day 1~7不重复。
2. **众包扩展(未来)**: 允许用户提交自己的行为,审核后加入公共库。
3. **AI生成(未来)**: 使用AI自动生成行为裂变、合成规则。

**监控指标:**
- 用户在行为工坊召唤次数分布(如果单次召唤>10次,说明内容库不足)。
- 用户反馈中"总是这几个""没新东西"的提及率。

---

#### 风险4: 技术实现复杂度(P1 - 中风险)

**风险描述:**
- 行为工坊的召唤/裂变/合成机制,需要复杂的逻辑匹配和规则引擎。
- 动效实现需要精细的CSS动画+状态管理,开发成本高。
- 小程序性能限制,可能导致动画卡顿、内存溢出。

**影响:**
- 开发周期延长,MVP无法按时交付。
- 用户体验差(动画卡顿、加载慢)。

**缓解措施:**
1. **简化规则引擎**: MVP阶段使用硬编码规则库(JSON配置),而非复杂算法。
2. **动效降级**: 优先实现"核心爽点动效"(击碎裂隙),次要动效可简化或去除。
3. **性能优化**: 使用CSS动画而非JS动画,避免复杂Canvas绘制,控制图片资源大小。
4. **真机测试**: 在低端Android机型(如小米RedMi)上测试,确保流畅度。

**监控指标:**
- 开发进度是否按计划完成。
- 真机测试时的帧率、内存占用。

---

### 8.2 关键假设(需验证)

#### 假设1: 用户愿意花时间"探索愿望"

**假设:**
- 用户不只是想"快速打卡",而是愿意花5-10分钟完成愿望排序游戏,澄清自己的核心愿望。

**验证方法:**
- 监控愿望排序页的停留时长(目标≥5分钟)。
- 监控愿望排序完成率(目标≥90%)。
- 用户反馈:"愿望排序游戏对你有帮助吗?"

**失败后果:**
- 如果用户只是想快速打卡,愿望排序会被认为"浪费时间",流失率高。

**备选方案:**
- 提供"快速开始"选项,使用默认愿望+默认卡组,让用户先体验Daily。
- 将愿望排序改为可选功能,而非必需流程。

---

#### 假设2: "击碎裂隙宣言"能提供足够的情绪价值

**假设:**
- 用户在完成微行动后,看到"裂隙宣言→击碎动画→鼓励台词"的三段式反馈,会有成就感和情绪价值。
- 这种反馈比传统打卡App的"✓打勾"更能激励用户持续使用。

**验证方法:**
- 用户反馈:"击碎裂隙的动画让你有成就感吗?"(1-5分)。
- 监控日均完成率(目标≥50%),与传统打卡App对比。

**失败后果:**
- 如果用户觉得"击碎裂隙"只是噱头,缺乏实际价值,日均完成率低。

**备选方案:**
- 增强动效(音效+粒子效果+屏幕震动)。
- 增加"掉落物品"机制(完成后掉落虚拟奖励)。

---

#### 假设3: 微行动足够小,用户能轻松完成

**假设:**
- 通过行为裂变,用户生成的"保底卡"足够小(30-60秒),即使再忙也能完成。
- 用户不会因为"任务太简单"而觉得没意义。

**验证方法:**
- 监控日均完成率(目标≥50%)。
- 用户反馈:"保底卡的难度是否合适?"(太难/合适/太简单)。

**失败后果:**
- 如果保底卡仍然太难,完成率低(<40%)。
- 如果保底卡太简单,用户觉得"没意义",流失率高。

**备选方案:**
- 动态调整卡片难度(根据用户完成率,自动推荐难度合适的卡片)。
- 提供难度选择(简单/中等/困难),让用户自主选择。

---

#### 假设4: 用户愿意在7天主线后继续玩

**假设:**
- 用户完成Day 7后,愿意选择"下一座愿望城",继续玩下一个7天循环。

**验证方法:**
- 监控Day 7完成后的回流率(目标≥50%)。
- 用户反馈:"你完成Day 7后,愿意继续选择下一座愿望城吗?"

**失败后果:**
- 如果Day 7完成后,用户认为"已经玩完了",回流率低(<30%)。

**备选方案:**
- 在Day 7剧情中,强化"这只是第一座愿望城,还有更多未探索"的引导。
- 增加长期成长线(等级/图鉴/成就),让用户有持续目标。

#### 9.2.2 理论基础

| 理论 | 核心观点 | 应用到产品 |
|-----|---------|-----------|
| 福格行为模型 | B=MAP(行为=动机×能力×提示) | 愿望=动机,微行动=降低能力门槛,每日卡片=提示 |
| 游戏化设计 | 核心循环+即时反馈+成长系统 | 每日完成→击碎裂隙→Day推进形成核心循环 |
| 心流理论 | 挑战与技能匹配时,用户进入心流状态 | 保底卡(低挑战)+主线卡(中挑战)匹配用户能力 |
| 自我决定理论 | 自主性+胜任感+关联感驱动内在动机 | 愿望排序=自主性,完成微行动=胜任感,Arc陪伴=关联感 |

### 9.3 术语表

| 术语 | 定义 |
|-----|------|
| MVP | Minimum Viable Product,最小可行产品,包含核心功能的初始版本 |
| 福格行为模型 | BJ Fogg提出的行为模型:B=MAP(Behavior = Motivation × Ability × Prompt) |
| 微行动 | Tiny Habits,极小的、容易完成的行为单元(如"刷牙后做2个深蹲") |
| 锚点 | 触发微行动的提示(如"刷牙后""起床后") |
| 愿望城 | 用户选择的核心愿望在游戏世界中的隐喻表达 |
| 裂隙之影 | 游戏世界观中的阻力象征(拖延/忙/没动力/觉得没意义) |
| 微行动咒语 | 微行动在游戏中的称呼,强化魔法感 |
| 保底卡 | 极低难度的微行动卡(30-60秒,难度★),即使再废也能完成 |
| 主线卡 | 中等难度的微行动卡(2-5分钟,难度★★),需要一定努力 |
| 彩蛋卡 | 趣味性微行动卡(10-30秒),随机出现,增加惊喜感 |
| Streak | 连续完成天数,核心游戏化指标 |
| Day | 7天主线的进度(Day 1~Day 7) |
| Arc | 弧光导师,克制温暖的NPC,负责主线引导 |
| MIA | 魔法师米娅,活泼发散的NPC,负责行为工坊引导 |
| Rift | 裂隙之影NPC,每天出现阻力宣言 |
